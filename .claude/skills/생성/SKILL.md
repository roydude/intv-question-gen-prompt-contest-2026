# /생성

1. 인자가 없으면 우선 직무 전체 평가(공통 케이스 10개, 질문 20개)를 만든다. 케이스를 주면 그 케이스만 만든다(케이스당 질문 2개). 케이스만 고르면 평가 점수는 계산하지 않는다.
   - 인자에 "확장"이 있으면 확장 연습(평가 미포함, 우선 직무 밖 직무 10개 × 평가 주제 2개 = 20케이스)을 만든다. 케이스를 함께 주면(예: P08, X-P17-C2) 그 케이스만. 참고 점수만 나오고 평가 점수·공식 점수에는 들어가지 않는다.
2. ③이 v9.0.0과 같거나 바뀐 분량이 3% 미만이면 생성이 막힌다. 막히면 이유를 그대로 전하고, 뜻 없는 문장으로 분량을 채우자고 하지 말고 실제 개선 방향을 함께 찾는다.
3. 실행 전에 `uv run app.py status`로 남은 질문을 확인하고, 이번에 쓸 질문 수와 함께 알려 준 뒤 진행할지 한 번 묻는다.
4. `uv run app.py generate [--ext] [--cases P01,P03] [--model ...] [--effort ...]`를 실행한다. 몇 분 걸릴 수 있으니 타임아웃을 10분으로 넉넉히 둔다.
5. 결과를 짧게 정리한다. 평가 점수(또는 질문 점수 평균, 확장 연습이면 참고 점수와 같은 케이스 v9.0.0), J1~J4, 많이 걸린 실패 유형, 규칙 진단 위반. 확장 연습이면 처음 보는 케이스 점검 결과(우선 직무와 확장 연습에서 v9.0.0보다 오른 폭)도 전한다.
6. 점수가 낮은 질문 2~3개를 결과 파일(runs/<실행 ID>.json)에서 찾아 근거(reasons)를 보여 주고, 프롬프트의 어느 규칙을 손보면 좋을지 제안한다. 골든셋의 참고 질문을 프롬프트에 옮겨 적자고 제안하지 않는다.
