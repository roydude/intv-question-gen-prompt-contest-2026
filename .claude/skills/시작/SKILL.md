# /시작

참가자가 처음 레포를 받았을 때 한 번 한다. 묻지 않고 처리할 수 있는 건 바로 처리하고, 참가자가 할 일은 마지막에 한 줄로만 알려 준다.

1. `uv --version`으로 uv를 확인한다. 없으면 설치 명령을 알려 주고 참가자가 직접 설치하게 한다.
   - macOS: `brew install uv` 또는 `curl -LsSf https://astral.sh/uv/install.sh | sh`
   - Windows(PowerShell): `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`
2. `uv run app.py setup`을 실행한다. 개인 브랜치를 GitHub 로그인 이름(없으면 git 사용자 이름)으로 만들어 올린다.
   - git 사용자 이름·이메일이 없다고 나오면 참가자에게 물어 `uv run app.py setup --git-name "이름" --git-email "메일"`.
   - 이름을 정하지 못했다고 나오면 영문 이름을 물어 `uv run app.py setup --name 영문이름`.
3. 화면을 띄운다. `uv run app.py`를 백그라운드로 실행한다(브라우저가 자동으로 열린다). 이미 8000 포트가 쓰이고 있으면 화면이 켜져 있는 것이니 http://localhost:8000 을 열라고만 알려 준다.
4. 참가자에게 이렇게만 안내한다. "브라우저 화면 맨 위 시작 준비 카드의 ② API 키 칸에 DM으로 받은 키를 붙여 넣고 저장하고 확인을 누르세요. 키는 이 대화창에 붙여 넣지 마세요."
   - .env는 열거나 읽지 않는다. 키를 대화로 받지 않는다.
   - Claude Code를 끄면 화면도 함께 꺼질 수 있다. 그때는 터미널에서 `uv run app.py`로 다시 켜면 된다고 알려 준다.
5. 규칙을 세 줄로 정리해 준다.
   - 한 사이클은 공통 케이스 10개 × 평가 요소 2개 = 질문 20개, 1인 상한은 질문 400개다. ③을 v9.0.0보다 5% 이상 바꿔야 질문을 생성하고 제출할 수 있다.
   - 생성할 때마다 실행 기록이 runs/에 남고 개인 브랜치에 자동으로 커밋·푸시된다. 기록은 고치지 않는다.
   - 마감 전에 `/제출`로 PR을 열고, 마감 시점의 마지막 커밋이 제출본이다.
