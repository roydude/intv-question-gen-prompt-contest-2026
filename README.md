# 잡다 면접 연습 프롬프트 콘테스트

잡다 면접 연습의 **질문 생성 프롬프트(③)** 를 개선하는 콘테스트예요. 각자 PC에서 화면을 켜고, 프롬프트를 고치고, 공통 케이스 10개로 질문을 만들어 AI 채점 결과를 보며 다듬어요. 마감 전에 개인 브랜치로 PR을 올리면 제출이 끝나요.

## 일정

| 언제 | 무엇 |
|---|---|
| 10/23(금) 오후 | 킥오프: 레포 초대, 규칙 안내, 시연 |
| 10/26(월) 오전 | PR 마감 (마감 시점 PR의 마지막 커밋이 제출본) |
| 10/26(월) 오후 | AI 평가와 블라인드 투표 |

## 준비물

- git, [uv](https://docs.astral.sh/uv/)
- 운영자에게 DM으로 받은 API 키
- (선택) [Claude Code](https://docs.claude.com/claude-code): 프롬프트 개선을 도와주고 `/제출`로 PR을 열어 줘요
- (선택) GitHub CLI `gh`: 로그인돼 있으면 개인 브랜치 이름을 GitHub 로그인 이름으로 정하고, `/제출`이 PR까지 열어 줘요

## 시작하기

터미널에서 한 줄이면 돼요.

```bash
git clone <운영 레포 주소> contest && cd contest && uv run app.py
```

처음 실행하면 이렇게 진행돼요.

1. 개인 브랜치를 GitHub 로그인 이름으로 만들어 올려요(예: `contest/roydude`). `gh`가 없으면 git 사용자 이름을 써요.
2. "DM으로 받은 키를 복사한 뒤 Enter를 누르세요"가 나오면, DM에서 키를 복사하고 Enter만 누르세요. 키는 이 PC의 `.env`에만 저장되고 끝자리 4자만 보여요.
3. 브라우저에 http://localhost:8000 화면이 열려요. 끌 때는 그 터미널에서 `Ctrl+C`.

터미널 안내를 놓쳤다면 화면 맨 위 **시작 준비** 카드에서 브랜치를 만들고 키를 붙여 넣으면 돼요. 다음부터는 `uv run app.py`만 실행하면 바로 화면이 열려요.

키는 Claude Code 대화창에 붙여 넣지 마세요. Claude Code에서 `/시작`을 입력해도 브랜치를 만들고 화면을 띄워 줘요(키는 화면에서 넣어요).

## 화면에서 하는 일

1. **프롬프트 편집**: 편집기 위 탭(②·③·④)에서 단계를 골라 고쳐요. 왼쪽은 v9.0.0 원문(읽기 전용), 오른쪽이 내 프롬프트예요. 채점 대상은 ③뿐이고, ②·④는 고쳐도 점수와 투표에 들어가지 않아요.
   - 회색으로 표시된 **입력·출력 형식 영역**은 키 이름과 JSON 구조를 바꾸지 마세요. 깨지면 생성이 실패하고 그 질문은 0점이에요.
   - 편집기 머리에 ③의 **바뀐 분량**이 보여요. 3% 이상이어야 질문을 생성하고 제출할 수 있어요.
   - 최근 결과·공통 케이스·남은 질문은 오른쪽 레일의 아이콘을 누르면 펼쳐져요.
2. **질문 생성**: 전체 케이스(질문 20개)로 만들면 평가 점수까지 나와요. 케이스를 골라 실행하면(케이스당 질문 2개) 질문 점수만 나오고, 같은 케이스의 기준선 평균과 비교해요.
   - 생성은 화면을 막지 않아요. 오른쪽 아래에 진행 상황이 보이고, 그동안 프롬프트를 계속 고치고 저장할 수 있어요. 진행 중인 생성에는 시작할 때 저장된 프롬프트가 쓰여요.
   - 끝나면 3초 뒤 결과 화면으로 넘어가요. 저장하지 않은 변경이 있거나 머무르기를 누르면 넘어가지 않아요.
3. **결과**: 평가 점수, J1~J4, 케이스별 질문과 근거, v9.0.0 질문을 비교해요. 케이스 이름 옆 아이콘을 누르면 오른쪽에 공고·지원자 정보가 열려서, 질문과 이력을 나란히 볼 수 있어요. 상단 바의 **기준 보기**에서 루브릭을 볼 수 있어요.

화면 없이 만들고 싶으면 Claude Code에서 `/생성`(또는 `uv run app.py generate`)을 써요. 같은 엔진, 같은 상한이에요.

## 규칙

- **상한**: 1인 질문 400개(한 사이클 20개 × 20번). 생성을 시작하면 바로 차감되고, 중간에 멈추면 이미 보낸 케이스만큼 차감돼요.
- **실행 기록**: 생성할 때마다 `runs/`에 기록이 남고 개인 브랜치에 자동으로 커밋·푸시돼요. 기록은 고치지 마세요. 고친 흔적은 git 기록에 남아요.
- **고칠 수 있는 곳**: `prompts/`뿐이에요. 코드와 데이터는 고치지 않아요.
- **생성·제출 조건**: ③이 v9.0.0과 같거나 바뀐 분량이 3% 미만이면 질문을 생성할 수도, 제출할 수도 없어요. 공백·빈 줄 차이는 세지 않아요.
- **골든셋**: 공통 케이스 10개는 모두 공개예요. 다만 참고 질문을 프롬프트에 옮겨 적거나 특정 케이스만 맞추는 규칙을 넣는 것은 지양해요.
- **API 키**: `.env`에만 넣고, 대화창·화면·커밋 어디에도 붙여 넣지 마세요. `.env`는 git에 올라가지 않아요.

## 채점

- 질문 하나의 점수 = J1 공고·평가 요소 정합(25) + J2 질문 명확성(50) + J3 경험 사실 정확성(20) + J4 설계도·채점 기준 일관성(5) = 100점
- J2는 실패 유형 C1~C5로 판정해요. 해당 없음 5점, 1개 3점, 2개 이상 1점이에요.
- **평가 점수** = 공통 케이스 10개에서 나온 질문 20개 점수의 평균
- 규칙 검사 16개(A00~A15)는 진단용이라 점수에 넣지 않아요. 단 A00(질문·답변 팁에 키 이름·ID 같은 내부 값 노출)은 실격이라 그 케이스 질문은 0점, 평가 점수는 계산하지 않아요.
- J2는 채점관이 reason 맨 앞에 적은 실패 유형 수로 상한이 정해져요(1개면 3점, 2개 이상이면 1점까지).
- 채점관은 이 밖에도 아래를 봐요(`contest/judge.py`).
  - 같은 지원자에게 나간 두 질문의 주제·평가 목적이 겹치면 J1 감점.
  - 답하라고 요구하는 행동이 2개 이상이거나, 장면을 여는 절("~할 때", "~한다면")이 2개 이상이거나 목적절과 조건절이 겹치면("~를 위해 ~했을 때") J2 3점 이하.
  - 입력에 없는 사실(수치·역할·회사)을 전제하면 J3 1~2점.
- 기준 점수는 v9.0.0을 같은 조건으로 3번 생성·채점한 평균이에요(62.2). 평가 점수가 기준 점수보다 낮으면 패널티가 있어요.
- 같은 프롬프트도 실행마다 점수가 조금씩 달라져요. 한 번의 점수보다 흐름을 보세요.
- 화면 점수는 연습 점수예요. 공식 점수는 운영자 PC에서 제출본 프롬프트로 다시 매겨요.

## 제출

```
> /제출
```

`prompts/`와 `runs/`를 커밋·푸시하고 main으로 PR을 열어요. 마감 전까지 다시 고치고 `/제출`하면 같은 PR에 커밋이 쌓여요. PR은 머지하지 않아요. 참가자끼리 서로의 PR이 보여도 괜찮아요.

## 우승

1. AI 평가 점수 리더보드(투표가 끝날 때까지 참가자 코드로 표시)
2. 상위 3명 블라인드 투표: 같은 지원자·같은 평가 요소에 대한 세 사람의 질문을 무작위 순서로 보고, 참가자 전원과 팀장이 1~3위를 매겨요(3·2·1점). 동점이면 AI 점수로 가려요.

## 폴더

| 경로 | 내용 |
|---|---|
| `prompts/` | 내가 고치는 프롬프트 (②·③·④) |

## 자주 막히는 곳

| 증상 | 해결 |
|---|---|
| 화면 맨 위에 "시작 준비" 카드가 떠요 | 카드의 ① 만들기, ② 키 붙여 넣기를 마치면 사라져요 |
| 키를 바꾸고 싶어요 | 상단 바 **설정** → **키 바꾸기** |
| "8000 포트를 이미 쓰고 있어요" | 이미 켜진 화면을 쓰거나 `uv run app.py --port 8001` |
| "기록을 올리지 못했어요" | 인터넷·GitHub 로그인 확인. 다음 실행 때 다시 올려요 |
| 편집기가 기본 입력창으로 열림 | 인터넷 연결 확인(편집기를 CDN에서 불러와요) |

`uv run app.py doctor`로 현재 상태를 한 번에 볼 수 있어요.
